# 1. 与你以前的 Vivado 操作怎样对应
## 原来的工作分给几个小工具完成

| 以前在 Vivado 中做什么 | 现在在哪里做 | 你应该关注什么 |
| 写模块文件 | VS Code 中编辑 .sv / .scala | 接口、位宽、逻辑、寄存器 |
| 写仿真文件 | VS Code 中编辑 *_tb.sv | 时钟、复位、输入变化与检查 |
| 点击运行仿真 | VS Code 任务调用 Icarus | 是否报错，是否出现 PASS |
| 查看波形 | GTKWave | 每个时间点的输入输出 |
| 写引脚和时钟约束 | 当前小模块仿真暂不使用 XDC | 上板阶段再按器件准备 |
| 综合、布局布线、下载板卡 | 尚未配置为本项目工作流 | 后续根据导师平台决定 |

testbench 就是你熟悉的“仿真文件”。例如 counter4.sv 是计数器设计，counter4_tb.sv 给它时钟、复位和 enable，并检查 count。仿真文件本身也用硬件描述语言编写，但角色不同。

## 两条常用路径
```text
手写 Verilog / SystemVerilog
       + 仿真文件
            |
          Icarus
            |
    终端结果 + VCD 波形 --> GTKWave
```
```text
Chisel 源码 + 固定版本配置
            |
   Scala CLI / Scala / Java / firtool
            |
      生成 SystemVerilog RTL
            |
 提取需要的主模块 + 适配器 + 仿真文件
            |
         Icarus 仿真
```

Chisel 的“生成成功”与仿真的“测试通过”是两项检查。当前生成任务将 RTL 打印到终端；检查已有 Chisel 模块的仿真任务读取仓库附带的 .generated.sv，二者没有自动覆盖关系。

# 3. Chisel 的依赖为什么还有几个版本号
## 工具版本与项目版本分开看

Scala CLI 是启动和构建工具；Scala 是编写生成程序的语言；Chisel 是硬件库及相关编译插件；Java 提供运行环境；firtool 把硬件中间表示进一步处理成 RTL。

| 项目依赖 | 本项目固定值 | 从哪里确定 |
| Scala | 2.13.16 | chisel_project.scala |
| Chisel | 7.2.0 | chisel_project.scala |
| Chisel 编译器插件 | 7.2.0 | chisel_project.scala |
| Java | 当前任务优先使用已有 Java 21 | vscode_run.py |
| firtool | 附带生成结果标注 1.133.0 | .generated.sv 文件头及生成流程 |

执行 scala-cli version 会显示它自带或默认选择的 Scala 版本，本机为 3.7.3。这不表示项目改用了 Scala 3；项目的 using scala 指令将实际构建版本固定为 2.13.16。

## 本机任务怎样选 Java 和依赖仓库
vscode_run.py 先查找已有 Java 21，再把 JDK 路径交给 Scala CLI，可避免每次依赖自动 JDK 选择。若没有可用的 Java 21，启动器才使用 --jvm 21，让 Scala CLI 管理下载。

任务会在该次子进程中将默认依赖仓库设为 Maven Central；如果你已经设置 COURSIER_REPOSITORIES，则保留你的值。没有重写全局 Maven 或 Java 配置。

## 示例文件的角色
| 文件 | 作用与修改方式 |
| SafetyGate.scala | 安全门源码；改后重新生成 |
| SyntaxBasics.scala | 语法综合源码；对照 Verilog 学习 |
| chisel_project.scala | 依赖与编译配置；先保持版本配套 |
| *.generated.sv | 已生成的主模块；改设计优先改源码 |
| *_adapter.sv | 对接测试平台；随接口变化调整 |

# 5. 每天打开项目与运行计数器
## 第一步：打开整个仓库

在 VS Code 使用“文件 → 打开文件夹”，选择 `D:\Projects\毕设`。不要只打开某个 .sv 文件，否则 VS Code 可能读不到根目录的任务菜单。

有两种窗口模式都能使用当前任务：Windows 窗口下，任务自动调用 wsl.exe 进入 Ubuntu-24.04；WSL 窗口下，任务直接在 Ubuntu 中运行 python3。

## 第二步：打开设计和仿真文件
```text
学习资料/配套示例/counter4.sv
学习资料/配套示例/counter4_tb.sv
```
前者描述计数器，后者是你熟悉的仿真文件。修改后先保存，再重新运行任务。

## 第三步：编译并执行仿真
按 Ctrl+Shift+B，执行默认任务“仿真：计数器（第 2 天）”。终端最后应看到：
```text
PASS counter4: reset/hold/increment/wrap
PASS: counter4
```
PASS 表示示例检查的复位、保持、递增和回绕行为通过；仍要结合代码理解它具体检查了什么。

## 第四步：打开波形
顶部菜单“终端 → 运行任务”，选择“波形：打开计数器波形”。该任务会先重新仿真，再打开 GTKWave，并预置 clk、reset、enable、count 四个信号和完整时间范围。

观察 reset 生效时 count 清零，enable 为 1 时逐拍递增，enable 为 0 时保持，15 再加 1 回到 0。GTKWave 是单独窗口，经 WSLg 显示在 Windows 桌面上。

> 这里的入口是任务菜单与 Ctrl+Shift+B。右上角通用的“运行文件”按钮通常不知道该把哪两个 RTL 文件一起编译，也不知道选哪个仿真顶层。

# 7. 不点菜单时，怎样手动运行
## Windows PowerShell：先打开项目

```powershell
Set-Location -LiteralPath 'D:\Projects\毕设'
code .
```
这只负责打开编辑器，不执行仿真。在这个 PowerShell 中，手动进入 Linux 可执行：
```powershell
wsl -d Ubuntu-24.04
```

## 进入 Ubuntu 后：定位与检查
```bash
cd '/mnt/d/Projects/毕设'
python3 学习资料/配套示例/vscode_run.py check
```
然后按需选一行运行，不必一次全执行：
```bash
python3 学习资料/配套示例/vscode_run.py counter4
python3 学习资料/配套示例/vscode_run.py wave
python3 学习资料/配套示例/vscode_run.py chisel
python3 学习资料/配套示例/vscode_run.py python
```

## 直接调用 Icarus 的最小过程
下面在 Ubuntu 的“配套示例”目录运行：
```bash
cd '/mnt/d/Projects/毕设/学习资料/配套示例'
iverilog -g2012 -s counter4_tb -o counter4.vvp counter4.sv counter4_tb.sv
vvp counter4.vvp
```
第一行工具命令将模块和仿真文件一起编译；-s 指定仿真顶层，-o 指定编译结果；第二行执行结果文件。手工运行时 VCD 出现在当前目录，任务入口则统一放到 .outputs。

用任务菜单就能完成本周学习；手工命令用于理解工具分工和排查问题。PowerShell 里的 D:\ 路径和 Bash 里的 /mnt/d 路径分别使用，不要混写。

# 9. 常见问题与维护
## 先判断问题属于哪一层

| 现象 | 优先检查 | 操作 |
| 运行任务列表为空 | 是否打开整个项目根目录 | 重新打开 D:\Projects\毕设 |
| PowerShell 找不到 iverilog | 当前终端是 Windows 还是 Ubuntu | 直接用任务，或进入 WSL |
| 找不到 counter4_tb | 是否编译了仿真文件并选对顶层 | 使用已配好的计数器任务 |
| 波形与修改前一样 | 文件是否保存、是否重新仿真 | 保存后重跑波形任务 |
| Chisel 出现下载错误 | Java、Maven 或后端下载的哪一层 | 保留完整报错与对应 URL |
| GTKWave 无窗口或提示显示错误 | WSLg 图形环境 | 用任务入口，它已配置 X11 后端 |
| 同名模块重复定义 | 是否混编了原模块与适配器 | 使用分别配置的测试任务 |

## VS Code 更新后的 WSL 后端
VS Code 的 Windows 客户端与 WSL 中的 VS Code Server 需要配套。客户端更新后，首次连接 WSL 可能下载对应版本的后端；这不等于 Icarus、Chisel 或你的源码丢失。

若后端下载缓慢，Windows 本地窗口下的现有任务仍会直接调用 wsl.exe，通常无需等待远程编辑后端才能执行仿真。下载完成前，避免把“连接编辑器失败”误判成“RTL 测试失败”。

## 更新与备份
源码、任务、教材源稿和生成示例由 Git 管理；.outputs、.scala-build、.bsp、tmp 等缓存由 .gitignore 排除。换一台电脑时，需要重新安装工具；克隆仓库只取得文件，不会自动安装 Linux 软件。

VS Code 与扩展可以自动更新，教学依赖暂保持固定版本。升级 Chisel、Scala 或插件前，先保留当前可用配置，再重新运行生成与六组 RTL 检查。
